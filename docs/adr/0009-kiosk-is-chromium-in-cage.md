# The screen is Chromium in cage, with the Hub's own on-screen keyboard

The Pi shows the Hub in Chromium, full-screen, inside [cage](https://github.com/cage-kiosk/cage): a Wayland compositor that shows one app and nothing else. There's no desktop, no taskbar and no window to close, so a stray touch can't leave the Hub, and if Chromium closes, systemd starts it again. cage runs as its own `kiosk` user, which can't log in, on the first console, which no longer offers a login prompt. The browser's profile lives in memory and starts fresh each time, so there's never a "restore pages?" prompt and nothing wears the SD card.

cage has no on-screen keyboard, so the Hub gets its own: a Svelte component that opens when a Shopping item or To-do is being typed. It can be sized to the Hub's 64px touch targets, looks like the rest of the Hub, and shows on the PC and in the screenshot tests like everything else. It was built in November 2026: it opens for any text box, anywhere on the Hub, and slides the page up so the box stays in view.

cage can't power the screen down: it doesn't offer the Wayland protocol that `wlopm` uses for that, and `vcgencmd display_power` doesn't work on a Pi 5. It does let `wlr-randr` switch its output off, which stops the picture, and the Waveshare then turns its backlight off. So for Lights out (AB#64), a small screen service, `familyhub-screen.service`, runs beside cage as the `kiosk` user. It asks the Hub every half a minute whether it's Lights out, reads the touchscreen itself, as Chromium can't see touches once the output is off, and switches the output off two minutes after the last touch and on again at a touch. Chromium doesn't get a touch made while the output is off (checked on the Pi), so once a touch has lit the screen, the service tells the Hub with `POST /api/screen`, and the page, asleep, asks every second and wakes, so one touch both lights the screen and wakes the Hub. Checked on the Pi in November 2026: the screen goes fully dark, touches still arrive, and the Hub comes back full-screen at the same size, without restarting.

## Considered Options

- **labwc with squeekboard:** Raspberry Pi OS's own compositor and keyboard, which opens by itself when Chromium has a box to type in, so the Hub needs no change. But labwc is a desktop compositor with more to lock down, and the keyboard's size and look aren't the Hub's to choose or test.
- **The full Raspberry Pi OS desktop with Chromium in kiosk mode:** the most familiar, but a desktop sits behind the browser to fall into, and there's much more installed and running than the Hub needs.
- **X11 with a bare window manager:** the older way to do this. Raspberry Pi OS has moved to Wayland, and Chromium's touch support is better there.
